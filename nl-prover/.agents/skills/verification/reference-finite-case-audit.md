# Finite Case and Computation Audit

Use this checklist when a proof depends on an exhaustive finite case split,
finite classification, symmetry quotient, sign/configuration enumeration,
brute-force check, small graph or matrix enumeration, polynomial or algebraic
computation, or a local script output.

## Verifier Checklist

1. Identify the finite universe.
   - Name the parameters, constraints, and admissibility conditions.
   - Check that the universe is finite under the original hypotheses.

2. Check exhaustiveness.
   - Explain why every admissible object appears in the listed cases.
   - If cases are generated by a construction, check that every output is
     admissible and every admissible input is produced.

3. Check reductions by symmetry or equivalence.
   - Name the relabeling, group action, quotient, normalization, or invariant
     used to reduce cases.
   - Verify that the target property is preserved under the reduction.
   - Record whether duplicates are harmless or intentionally removed.

4. Check representative evidence.
   - Require a table, worked representative calculations, local derivation, or
     local command/output path that can be re-read without external services.
   - A bare sentence such as "all cases were checked" is not evidence.

5. Check edge cases.
   - Audit boundary, degenerate, parity, zero, minimal, maximal, repeated-root,
     orientation, disconnected, or empty cases when they can occur.

6. Map evidence to the conclusion.
   - For each table row, representative, or computation result, state exactly
     how it proves the needed claim or rules out the forbidden case.

## Packet Routing

For a passing lemma or global proof, the review packet must record
`Unresolved finite-check blockers: NONE` whenever this audit applies.

Use `REVISE_PROOF` when a table, representative calculation, local derivation,
or local artifact can repair the proof without changing the route.

Use `REVISE_PLAN` when the finite universe, reduction, or case split itself is
wrong, incomplete, or too broad to repair locally.

Use `HUMAN_REVIEW` only when the finite cases depend on an ambiguous definition
or convention that cannot be normalized from accepted context.
